# FAMLIES PI publication database

Builds `site/config/publications.json` and `site/config/publications.bib`.
The page `site/publications.html` (with `publications-db.js` and
`publications-db.css`) displays them, with search, filters,
grouping, a FLAME-style numbered list or a sortable table, per-paper BibTeX/APA, and
BibTeX/CSV export of the filtered set. The page opens with all papers newest
first under year headings; the Year and Impact (OpenAlex citation count)
buttons reorder (click again to reverse), and "Advanced search" opens field
search, people/type/year/venue filters and display options. Preview locally: `python3 -m http.server 4176 --directory site` (from the repository root)
and open http://localhost:4176/publications.html.

## Update

```
cd scripts/pubs
python3 fetch_openalex.py --refresh   # OpenAlex works for each OpenAlex author ID in people.json
python3 fetch_flame.py                # UT FLAME publication list + its BibTeX page
python3 fetch_core.py                 # FLAME/BLIS/PLAPACK papers by anyone (for the citation test)
python3 find_coauthors.py             # frequent coauthors -> coauthors.json
python3 build_db.py                   # writes cache/core_ids.json (needed next)
python3 fetch_coauthors.py            # coauthors' works that cite a core paper or match keywords
python3 build_db.py                   # merge, filter, dedupe -> site/config/
python3 check_grants.py               # which 2026+ papers acknowledge a FAMLIES award
python3 build_db.py                   # (again, to record the grant results)
```

`fetch_*` write raw responses to `scripts/pubs/cache/` (git-ignored). Without `--refresh`,
`fetch_openalex.py` reuses the cache. OpenAlex without an API key allows only
a small daily budget per IP address, so avoid repeated refreshes.

## Adding Google Scholar data

Google Scholar has no API and blocks automated access, so the scripts never
contact it. To include Scholar entries (with Scholar's BibTeX):

1. Open a PI's Scholar profile in a browser, tick the "select all" box above
   the article list (use "Show more" first to list everything), then choose
   Export → BibTeX.
2. Save the file as `scripts/pubs/imports/<name>.bib` (any name ending in `.bib`).
3. Run `python3 build_db.py`.

Imported entries are matched to existing ones by DOI, arXiv ID or title. Their
BibTeX is used in place of generated BibTeX, and papers missing from
OpenAlex/FLAME are added. Entries without a PI/co-PI in the author list are
dropped. Any hand-written `.bib` file in `scripts/pubs/imports/` works the same way.

## Curation

- The FAMLIES working-note BibTeX files `site/config/fawns.bib` and
  `site/config/related.bib` are included as a source; add FAMLIES working
  notes there.
- `people.json`: PIs/co-PIs (`"group": "pi"`) and FLAME/BLIS collaborators
  (`"group": "collaborator"`), their OpenAlex author IDs (OpenAlex often splits
  one person across several IDs), and name regexes used to recognize them in
  author lists.
- `curation.json`:
  - `exclude_titles`: title regexes to drop.
  - `include_titles`: titles to keep for a person despite `person_rules`.
  - `person_rules`: `min_year` and `require_pi_coauthor` guard against
    OpenAlex author profiles that mix in other people with the same name.
    (The OpenAlex "Margaret Myers" profile includes a librarian, a UK
    software-metrics author and a China/Latin America policy analyst.)
  - `group_rules`: rules for everyone in a group. For collaborators, `fields`
    keeps an OpenAlex record only if its OpenAlex research field is listed;
    this removes same-name authors in other disciplines (e.g. the OpenAlex
    "Kyungjoo Kim" profile also contains a pulmonologist's papers).
  - `merge`: lists of titles that are versions of the same paper.

Who is included:
- FAMLIES PIs/co-PIs (`group: pi`) and other FAMLIES personnel (`staff`,
  currently Bimal Gaudel): all of their papers.
- FLAME/BLIS collaborators listed in `people.json` (`collaborator`) and
  frequent coauthors (`coauthor`: at least 3 distinct publications with a
  PI/co-PI since 1997, generated by `find_coauthors.py`; settings under
  `coauthors` in `curation.json`): only papers that pass the scope test below.
  For coauthors only those works are downloaded, since their full output
  (about 9,000 works) is mostly unrelated.

Scope (`relevance` in `curation.json`): any other publication is kept only if it is
FLAME/BLIS/PLAPACK-related, or cites at least one such paper according to
OpenAlex's reference lists. Related means: on the FLAME publication list or in
the FAMLIES BibTeX files, or its title/abstract/venue matches the
case-sensitive `keywords` regex (FLAME, libflame, PLAPACK, POOCLAPACK, BLIS).
Each kept entry records `"relation": "related"` or `"cites"`. OpenAlex has no
reference list for many older papers, so those can only qualify by keyword;
use `keep_titles` to keep one by hand.

Page buttons:
- **Core Team**: papers by a PI/co-PI or Bimal Gaudel (groups `pi`, `staff`).
- Scope dropdown, default **FAMLIES Related**:
  - **FAMLIES only**: papers acknowledging an NSF FAMLIES award
    (OAC-2513927/2513928/2513929, `famlies_grants` in `curation.json`).
    `check_grants.py` looks for the award numbers in the PDFs of 2026+ papers
    and via OpenAlex full-text search; papers checked by hand go in
    `acknowledged_titles`. Stored as `"grant": true`.
  - **All**: everything in the database.
- **FAMLIES Related** (`famlies_related` in `curation.json`, stored as
  `"famlies": true`): any paper by van de Geijn; any PLAPACK, FLAME,
  Elemental, ROTE or FAMLIES paper (on the FLAME publication list or in the
  FAMLIES BibTeX files, or the name appears case-sensitively in title,
  abstract or venue; "Elemental" only together with matrix/linear
  algebra/distributed); and any paper that cites one of those papers in the
  database. `not_core_titles` lists FLAME-list entries that are off-topic.

Dissertations come from the FLAME publication list. OpenAlex dissertation
records with more than one author are ignored, because OpenAlex lists the
advisor as a coauthor (sometimes first).

To add a person: add an entry to `people.json`, run `fetch_openalex.py`
(fetches only IDs not yet cached), then `build_db.py`.

Within one paper the canonical version is chosen in this order: journal,
conference, book, chapter, thesis, report, preprint. The other versions
(e.g. FLAME Working Notes, arXiv) are shown as extra links.
